### 1. What the LinuxGSM page says (and what it means for you)

I read the page you linked. The points that affect your plan:

- **Requirements:** a Hytale account that owns the game (needed even to download the dedicated server), Java 25, and at least 4 GB of RAM, with a download of about 3.5 GB.
- **Two one-time logins:** one during `install` (the downloader) and one on the first `start` (the server). Each is approved once in a browser and then saved and renewed automatically.
- **Credentials live in files** that LinuxGSM backups include, so backups must be kept private.
- **The server login is tied to the machine,** so a restored backup on another machine needs a new login.
- **Port:** 5520 over UDP, which matches what the UDP kit assumes.

So, concretely:

- **Sizing:** the docs say 4 GB minimum. As a starting point I'd give the container 6 to 8 GB of RAM and about 20 GB of disk on the NVMe ZFS storage, then watch real usage. That's my suggestion, not a documented figure. Headless has the room.
- **Container template:** use a current Debian or Ubuntu template and let LinuxGSM install Java as its dependency. I haven't checked which releases package Java 25, so if the dependency step fails on yours, that's the first thing to report.
- **Credentials stay out of git and out of anything you paste.** That includes login URLs and codes, the two credential files, and any password in `config.json`. Treat the game directory as private data in your backup plan.
- **Restore tests will need one extra step:** after restoring the game server to a new machine, you'll have to approve a fresh server login. Add that to the restore checklist.
- **Worth confirming:** whether each invited player can run the game. The page only covers the server's account, and I haven't checked what players need.
- **A possible shortcut:** the page says LinuxGSM can send the login link as an alert and names Discord and ntfy. As far as I know, it supports Gotify too. Check its alerts documentation, because that would give your phone a real job immediately.

### 3. Testing the UDP tool without DJV22

You can do most of the ladder now by making a **stand-in relay** on your LAN: a second small container (512 MB is plenty) running SSH and Python 3. Use its LAN address as `<RELAY>` in the runbook.

- **Rungs 1 to 4 become real:** a genuine SSH reverse tunnel between two separate hosts, a genuine entry end, and a genuine LAN client. Only the "gateway forward" step is missing.
- **The full path with the real game works too:** run the exit end and the tunnel at the game container, point the exit end at the Hytale server, and join from the Client through the stand-in relay's address.
- **Left for DJV22:** only rung 5 (a helper on a different network) and the real port forward on his gateway.

Please keep SSH off your daily-use desktop. A throwaway container is cleaner and mirrors the real relay.
