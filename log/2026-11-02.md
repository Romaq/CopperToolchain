### A bug that the move to `log/log.md` introduces

When a new session file has no user turns yet, `log-turn.sh` looks back through older logs to continue the numbering. It searches the dated files first and falls back to `log.md` at the repo root. Now that the founding log lives at `log/log.md`, the `log/*.md` pattern also matches it, and alphabetically that file sorts ahead of every date-named file. The script then picks up the founding log's last turn number instead of your latest dated session.

I reproduced this with fixtures: the founding log ended at turn 11 and a dated session at turn 14, and a new session started at **turn 12 instead of 15**. It would bite you on the first day-rollover or `--session` run, and it can't hurt the sessions you're in today.

**The fix** is one line in `scripts/log-turn.sh`, in the fallback loop:

```bash
# before
for f in $(ls -1r "$root"/log/*.md 2>/dev/null || true) "$root/log.md"; do

# after
for f in $(ls -1r "$root"/log/[0-9]*.md 2>/dev/null || true) "$root/log/log.md" "$root/log.md"; do
```

Only date-named files are checked first, then `log/log.md`, then the old root `log.md` for anyone who hasn't moved it. I tested three cases with the patch:

- A new `--session` file while a dated file at turn 14 exists continues at **15**.
- Same-day continuation then goes to **16**.
- With only the founding log present, the first dated entry continues from its last turn.

Please apply it by hand, since your copy differs from mine only in comments, and commit it.
